01
INVENTORY · INVENTORY

查询当前库存数量，并定位货物所在的库位与容器

Inventory 是仓库的库存查询台账。它将商品、数量、状态、Location、LP 以及关联的收货单、订单和 Load 汇集在同一入口，帮助操作人员确认当前库存处于哪个作业阶段、存放在哪里。

核心场景

出库前核查某个 SKU 是否有货，以及库存分布在哪里

例如客户询问某个 SKU 能否满足一批出库需求，操作人员先按 Customer、SKU 和 Open 状态查询总量，再进入明细确认库存所在的 Location 与 LP。若要判断订单实际还能锁定多少，还需结合 Inventory Lock 查看已经被其他订单占用的数量。

Summary

先按商品查看库存汇总

Summary 将符合查询条件的库存按 SKU、Status 和 Type 汇总，适合先判断某个商品当前有多少库存；需要确认具体库位、LP 或关联单据时，再切换到 Inventory Detail。

归属与商品

Customer、Title 和 SKU 用于限定库存属于哪个客户、货权方和商品。

状态与存放位置

Status、Location、LP 和 Original LP 用于查询库存所处阶段及当前或来源容器。

业务来源

Receipt、Order 和 Load ID 用于沿入库、出库或装载单据追查对应库存。

Total Qty (UOM)按当前计量单位显示

例如 5 CASE，表示以箱为单位记录。

Total Base Qty (UOM)换算为基础单位

若 1 CASE = 12 EA，则 5 CASE = 60 EA。

判断可分配量页面库存数量不等于当前可分配数量

Open 库存还需扣除已锁定数量：100 EA - 30 EA = 70 EA 可分配。

Inventory Detail

把商品汇总量拆解为具体库存记录

同一个 SKU 可能分布在不同客户、货权、LP、批次或库存状态下。Inventory Detail 按记录逐行展示这些差异，用于确认某一部分库存的实际归属和存放载体。

01
归属对象

Customer 表示库存所属客户，Title 表示库存货权。即使 SKU 相同，归属不同的库存也会分别记录。

02
商品与数量

SKU 识别商品；Qty (UOM) 显示当前单位下的数量，Base Qty 统一换算为基础单位。

03
库存属性

Status 表示当前作业阶段，Type 表示货物类型，Lot# 用于区分需要批次追踪的库存。

04
容器与追查入口

LP 表示当前承载库存的容器；点击 View 可进入该条库存记录，继续查看 Location 和关联单据等信息。

实际使用：Summary 用于判断“这个 SKU 总共有多少”，Inventory Detail 用于回答“这些数量分别属于谁、装在哪个 LP、处于什么状态”。

02
INVENTORY · INVENTORY LOCK

在库存真正拣出前，为订单保留可履约数量

Inventory Lock 记录出库订单或装配任务已经预留的库存，避免同一批可用量被重复分配。锁定只影响后续订单还能分配多少，不会立即减少 Inventory 页面中的库存台账数量。

核心场景

多个出库订单需要同一 SKU，先为准备履约的订单保留库存

当可用库存无法同时满足所有订单时，仓库先决定本轮需要处理的订单并执行 Commitment。系统为这些订单建立 Lock，后续订单便不会重复使用已预留的数量；若客户取消订单或仓库重新安排履约顺序，再通过 Rollback 释放占用并重新分配。

数量关系：Open Inventory 100 EA − Active Lock 30 EA = 其他订单仍可分配 70 EA。Inventory 台账仍显示仓库现有 100 EA，直到实际拣货后库存状态才发生变化。

与 Inventory Commitment 的关联

Commitment 执行库存分配，Inventory Lock 保存分配结果

用户不会在 Inventory Lock 页面手工建立锁定。锁定主要从 Outbound Inventory Commitment 产生；Order Dispatch 自动执行 Commitment 时，也会走同一套锁定逻辑。

02 · 执行分配Commit

系统按商品与库存属性匹配可用的 Open Inventory。

成功分配的数量形成锁定，防止被其他订单再次使用。

锁定记录

查看哪些订单正在占用库存

当订单缺货、需要取消或准备重新分配时，可按 Order ID 或 SKU 找到对应 Lock，确认占用数量、Customer、Title、Lot No 和当前状态。列表用于查询与导出，不提供人工新建或释放入口。

Lock Detail

确认这笔库存被谁占用，以及锁定是否仍然有效

客户询问订单为何缺货，或仓库准备取消、回滚并重新分配时，进入 Lock Detail 核对下面三项。

01
哪张订单占用

Order ID、Order Line ID 与 SKU 定位产生库存需求的订单及行项目。

02
占用了多少、是否仍有效

Qty / UOM 与 Base Qty 显示锁定数量，Status 判断它仍在占用、已被拣货还是已经释放。

03
按什么条件匹配库存

Customer、Title ID 与 Lot No 用于核对 Commitment 当时匹配的库存归属与批次条件。

Available Qty 什么时候有值？当订单需要 100 EA，但执行 Commitment 时只有 70 EA 可用，库存不足记录中的 Available Qty 会显示 70 EA。它保存的是当次锁定时系统找到的可用数量，之后不会随库存变化更新；锁定成功的 Active 记录通常显示“−”。

03
INVENTORY · INVENTORY ACTIVITY

沿库存作业轨迹，追查货物经历过的每一次变化

Inventory Activity 保存收货、补货、拣货、包装、装车、发运及调整产生的操作记录。它用于还原库存何时因哪项作业发生移动或变化，是查询和审计入口；Activity 本身不会再次修改库存。

核心场景

库存位置或数量与预期不符，需要回看它经历了什么

例如某个 SKU 原本位于储存区，现场却发现它已进入拣货容器。操作人员可按 SKU、LP 或 Location 查询 Activity，结合 From、To、Task ID 和 Created Time，确认这批库存是否因补货或拣货任务发生了移动；若来源是库存调整，还能继续通过 Adjustment ID 追溯审批记录。

确认需要追查的商品及库存归属。

比较变更前后的 LP 与 Location。

最后追溯来源Task / Adjustment

页面用途

查看库存“发生过什么”，而不是“现在还有多少”

Inventory Activity 保存已经发生的库存活动，用于调查库存为何增加、减少、换容器、换库位或进入后续出库阶段。当前库存数量应以 Inventory 或 Balance Report 为准；需要追查历史原因时，再回到本页面按 SKU、LP、Location、Task ID 或 Adjustment ID 查询。

01
查看发生的动作

02

From / To LP 与 From / To Location 用于判断库存从哪个容器和库位移动到了哪里。

03

Task ID 或 Adjustment ID 指向触发活动的任务或调整单；当前不能直接跳转，可复制 ID 到对应页面查询。

04
INVENTORY · LP

用一个可扫描编号，识别并追踪整托、整箱或整料箱库存

LP（License Plate）是托盘、纸箱、周转箱等库存载体在系统中的编号。它把库存、库位和作业状态关联起来，让操作人员无需逐条识别库存，即可通过扫描 LP 完成收货、上架、拣货、打包和装车中的确认与追踪。

核心场景

货物在仓库中不断更换位置和载体，LP 保留可追踪的库存归属

收货后，库存先装入托盘或容器 LP；上架时扫描 LP，将整组库存移动到目标库位。出库过程中，库存又可能进入拣货料箱、纸箱和外层发运单元。系统通过每个阶段的 LP，持续确认这批库存在哪里、装在哪个载体中，以及正处于哪个作业阶段。

入库与存储整托或整箱上架

库存装入 LP 后，通过标准上架或移动作业，将 LP 与其中的库存一起更新到目标库位。

拣货与发运扫码识别作业载体

拣货库存进入料箱，打包后进入纸箱；后续打包、装车和发运继续扫描对应 LP。

包装层级纸箱归集到外层单元

Parent LP 记录子箱与外层发运 LP 的包含关系，便于按整组识别纸箱和关联库存。

LP List

查询载体当前的位置、状态和用途

可按 LP ID、Type、Location 和 Status 查询现场载体。列表同时提供单个或批量创建、标签打印和详情入口；它用于查询与维护 LP，不直接执行库存移动。

Type

区分库存托盘、拣货料箱、纸箱及发运单元等不同载体角色。

Location / Status

确认 LP 当前所在库位及所处的收货、在库或出库阶段。

Add / Batch Create

预先建立单个或一批空 LP；创建后仍需通过业务作业装入库存。

标签打印：LP 标签将系统编号与现场托盘、纸箱或料箱对应起来，供手持端在收货、上架、拣货、打包和装车时扫码识别。标签内容由所选模板决定。

LP Type

不同类型表示库存当前使用的载体或作业角色

创建 LP 时应按照实际用途选择 Type。ILP、TLP、CLP 和 SLP 对应最常见的库内存储、拣货、包装和发运载体；HLP 主要用于任务或设备等临时逻辑挂载，RLP 用于退货场景。

ILP库内存储、收货与上架使用的库存 LP
TLP拣货和周转过程中使用的料箱 LP
CLP打包后形成的纸箱或包裹 LP
SLP合托、装车或发运归集使用的外层 LP
RLP承载退货、待检或待重新入库库存的 LP
HLP任务、设备或临时作业使用的逻辑 LP
Create LP

先建立可扫描的载体编号，再通过仓库作业装入库存

Add 创建一个空 LP；Batch Create 按 Type 和数量批量生成空 LP。两者都不会同时创建库存。

Type

必填，决定 LP 用于存储、拣货、纸箱、发运或退货等哪种场景。

Code

可留空，由系统按 LP Type 自动生成连续编号。

Location

可指定 LP 的初始位置，但不代表该 LP 已经包含库存。

LP Detail

确认这个载体在哪里、属于哪一层，以及里面当前装有什么

详情页用于核对 LP 本身与当前库存的关联，不是历史流水。库存经历过哪些移动，应到 Inventory Activity 查询。

01
Basic Information

Type、Status 和 Location 说明载体用途、当前作业阶段及所在位置；HLP Category / Reference 仅在逻辑 LP 场景下用于识别关联对象。

02
Parent LP

表示包装包含关系，例如多个纸箱 CLP 归集到一个外层发运 SLP；它不是库位层级。

03
Inventory List

展示当前关联到该 LP 的 SKU、数量、库存状态、批次和库位，可直接确认载体中现有的库存记录。

操作边界：库存装入、拆出或更换库位，应通过收货、上架、补货、拣货、打包或 Adjustment 等对应业务完成，不应把 LP 页面当作库存移动入口。

05
INVENTORY · ADJUSTMENT

通过可审批的调整单，纠正库存数量、位置和属性差异

Adjustment 不只用于修正库存数量。当库存被记录在错误的 LP 或库位，或者状态、货权、质量分类、批次及日期等信息有误时，也可以通过调整单进行更正。保存单据不会立即改变库存，只有审批成功后，整张 Adjustment 才会执行并留下可追溯记录。

核心场景

盘点发现实际库存与系统数量不一致

操作人员先找到对应库存，创建 Adjust Qty 并将目标数量填写为 18 EA。复核人员确认差异原因后批准单据，库存才从 15 EA 更新为 18 EA，同时生成 Inventory Activity。这样既纠正当前库存，也保留是谁、因为什么原因进行调整的记录。

Adjustment 的创建来源 除了操作人员在网页中创建，盘点和部分库存业务也会由系统生成调整单。
人工创建现场发现库存问题

发现破损、丢失、找回、收货差异或资料错误时，由操作人员创建 Adjustment。

盘点自动生成Cycle Count 出现差异

Count Result 审批后，系统自动创建并批准相应的 Adjustment。

其他业务自动生成LP 删除或 Assembly

删除仍含库存的 LP 时，系统自动生成调减单；Assembly 生成的调整单为 NEW，仍需人工审批。

Adjustment List

查询调整原因、类型与审批结果

可按 Customer、Status、Adjustment Type 和 Reason 定位调整单。NEW 单据可在列表右侧直接 Approve 或 Edit；点击 View 进入详情页后，还可以选择 Decline。已完成审批的单据仅保留 View，用于核对审批结果和库存变化。

NEW已保存，等待审批；库存尚未变化
APPROVED全部调整行执行成功，库存已经更新
DECLINED在 NEW 单据详情页点击 Decline；库存不会更新

Batch Approve：可一次批准多张 NEW Adjustment。只要其中一张或一行执行失败，本次批量审批整体不生效，不会留下部分成功的库存变化。

Create Adjustment

先选中需要纠正的库存，再填写调整后的目标值

Basic Info 先确定 Customer、Reason 和备注；Add Line 再按 SKU、Title、Location、LP 或 Lot No 查找来源库存。选择 Adjustment Type 并填写目标值后，将记录加入 Adjustment Lines，最后保存并按需要审批。

选择本次需要纠正的库存内容

不需要逐项记忆所有类型，只需先判断本次差异属于数量、存放位置、业务属性还是追踪资料。

数量差异Add Inventory / Adjust Qty

没有来源库存时使用 Add Inventory；已有库存数量不正确时，使用 Adjust Qty 修正目标数量。

用于更正批次号、生产日期或失效日期等批次追踪信息。

Auto Approve：保存后立即尝试批准，适合不需要二次复核的人工调整；如果审批失败，已保存的单据仍保留为 NEW。

Adjustment Detail

核对库存从什么值调整到了什么值

详情页将调整原因、审批状态和每一条变化放在一起，用于确认库存具体改动了多少，以及后续到 Inventory Activity 继续追溯。

NEW 单据操作：从列表点击 View 进入详情页，右上角可选择 Approve、Decline 或 Edit。Approve 后执行库存调整；Decline 后单据变为 DECLINED，库存保持不变。

01
Adjust From

调整前的数量、状态、LP、Location 或其他库存属性。

02
Adjust To

审批执行后的目标值；数量调整中表示调整后的总数量。

03
Adjust Qty / To LP

Adjust Qty 显示本次增加或减少的数量；To LP 显示库存要转入的目标载体。只有对应的调整类型才会显示数值，其他类型可以为空。

避免调整作业中的库存

系统没有统一阻止已锁定、已拣货、已打包或已装车库存被人工调整。操作前应先确认库存未处于正在执行或已完成的出库流程。

审批前核对调整内容

确认 Adjustment Type、Adjust From、Adjust To、Adjust Qty 和 To LP 与实际处理一致，再执行 Approve。

批准后通过反向单纠错

APPROVED 单据不能编辑、取消或撤回；如调整有误，应创建一张反向 Adjustment，保留完整审计链路。

06
INVENTORY · MIN/MAX SETTING

拣货区库存不够时，自动从储存区补货

Min/Max Setting 为每个 SKU 设置拣货区的最低和最高库存水位。当目标区域库存低于 Min Qty 时，系统创建 Replenishment Task，指导操作员从储存区搬运库存至拣货区。任务创建不会立即改变库存，完成 Collect 与 Drop 后库存位置才更新。

核心场景

拣货位库存即将耗尽，提前安排补货

某 SKU 每日出库量为 200 EA，但拣货区只能存放 100 EA。若等到拣货员发现库位已空再人工安排补货，订单会停在现场等待。配置 Min/Max 规则后，系统在库存低于 Min Qty 时生成补货任务，让操作员提前从储存区搬货。

01 · 检测当前库存低于 Min Qty

CYCLE COUNT · COUNT TICKETS

先确定盘点对象与规则，再把范围拆成现场任务

Count Ticket 是一次盘点的计划单。它记录为哪个客户盘点、按库位还是商品确定范围、采用哪种计数方法，以及是否隐藏系统数量。保存 Ticket 不会改变库存；创建 Count Task 后，现场人员才开始执行盘点。

使用场景

现场发现库存可能不准，需要安排一次复核盘点

例如拣货员发现某片库位的实物与系统记录可能不一致，主管可以建立 Count Ticket，圈定需要复核的库存范围并安排人员清点，而不是直接修改库存。盘点完成后复核差异，确认有误时再通过 Adjustment 更正库存。

Count Type / Count Scope确定盘点范围

Count Type 决定按库位、商品还是商品与库位组合选择；Count Scope 是本次实际纳入盘点的具体库位或商品。

Count Method现场按什么单位清点

Simple Qty / Piece 用于数量盘点，Case 按箱数比较，Pallet / Simple LP 用于托盘或 LP 维度核对。

Count Category为什么发起这次盘点

Daily / Cycle 走标准流程；Full 自动覆盖客户全部库存；Picking Exception 与 Full Air ROB Count 由特定场景自动建任务。

Blind Count是否隐藏系统数量

开启后不显示 System Qty 与 Expected Qty，避免操作员参考账面数填写；SKU、LP 和 Location 仍然可见。

盘点期间不冻结库存：仓库可以继续收货、拣货和移动库存。系统在提交盘点结果时读取当时的库存数量并计算差异；如果清点后到提交前发生了库存变动，可能影响差异结果，建议清点完成后及时提交。

CYCLE COUNT · COUNT RESULTS

复核每一条盘点结果，并决定是否据此更正库存

Count Results 汇总操作员提交的实盘数量及其与系统数量的差异。仓库主管在这里确认结果、批准或拒绝差异，也可以在无法直接判断时发起 Recount；页面记录的是盘点结论与处理进度，不是当前库存余额。

使用场景

实盘数量与系统记录不同，需要主管决定是否调整库存

例如系统记录某商品为 1 EA，现场实盘为 10 EA，Count Result 会显示差异 9 EA。主管先确认该结果已被查看，再结合商品、LP、库位和盘点证据决定批准、拒绝，或安排复盘；只有批准有效差异后，系统库存才会更新。

Approve Count Result

弹窗再次列出 System Qty、Count Qty 与 Difference。需要新增库存时，应确认正确的 Title (Owner)；勾选 Transfer difference inventory to On-Hold status 后，本次新增的差异库存会先进入 On-Hold，适合仍需质检或进一步确认的情况。

MATCH 结果：仍需完成 Acknowledge 和 Approve 才会关闭，但因为没有差异，不会生成 Adjustment。

无法确认时

Create Recount Task
